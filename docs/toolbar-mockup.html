Portal: native views in Emacs

Native WebKit pages and Ghostty terminals inside macOS Emacs panes, backed by one Swift dynamic module.

Build and run

The single build command produces build/portal.bundle and build/portal-host.

Shared keyboard controls

Terminal, Excalidraw, and HTML/Markdown views use portal-input-prefix (default C-b). The app receives ordinary keys, including Escape and C-g.

States & spec

Native toolbar

A 28 px strip that Swift draws at the top of every native view. It holds only controls that act on the view itself, and clicks never go back to Elisp. Anything that is Emacs behaviour (splits, buffers, files, key help, closing) stays in Emacs. The file name lives in the mode line.

Ownership dot

22 × 22 hit area, 8 px dot, 5 px inset. Shows who has the keyboard; a click switches it.

View controls

Right-aligned. 22 px buttons, 14 px icons, 2 px gap, groups split by 1 px rules. Icon only; the tooltip gives the name.

3

Value readout

Current zoom or text size. Dim at the default; clicking resets it.

4

Reserved strip

Swift takes 28 px from the top of the rectangle Emacs gives it. Nothing overlaps content, and the height never changes.

Find in page · replaces controls while open

3 of 12

Native WebKit find. Stays inside the strip, so the page is never covered. Escape or × closes it and the controls come back.

Theme · colors come from Emacs faces

Strip ← header-line, icons ← shadow, app dot ← success, toggled ← link. Sent once on load and on each theme change; nothing flows back.

Configuration

portal-toolbar t (default)

portal-toolbar nil · view fills the window body, no dot

;; Show or hide the strip everywhere; applies live
(setq portal-toolbar t)
 
;; The same native functions, reached from Emacs
(keymap-set portal-mode-map "+" #'portal-zoom-in)
(keymap-set portal-mode-map "t" #'portal-toggle-toc)

Swift is the only place view state lives. The Elisp commands call into it and read the value back; they never keep their own copy.
