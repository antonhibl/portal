implements explicit NS methods, and restores content, layer state and child

user's compilation settings. Unchanged role parameters are filtered too, since
setting =parent-frame= to its existing nil still calls an EmacsWindow-only method.

Global shortcuts and command sessions remain the next tasks. Finish or cancel

An Elisp presentation function runs an interactive command inside the dedicated
launcher frame and cleans up on success, cancellation, errors or loss of focus.
This replaces the temporary-frame behavior of M-x's =present= / =my/popup-command=
without taking command logic or completion out of Emacs.

*** Blocked by

lifecycle. Test with direct Elisp invocation; global shortcuts are not a
prerequisite for this task.

*** Plan and decisions
- Keep one active command session and a customizable command function, not
  serialized Elisp expressions or a provider/plugin framework. Validate that
  configured commands are interactive. A second invocation dismisses the current
  session rather than accidentally starting another recursive edit.
- Use the launcher's own minibuffer and synchronize Lisp frame visibility with
  native presentation. Preserve the original Emacs frame/window selection;
  restore it after closing if still live. Keep nested prompts in the launcher.
- Distinguish cancellation, loss of focus and successful external actions.
  Cancel a live launcher minibuffer before changing frames. Restore the previous
  application's focus on cancellation, but do not steal focus from a newly
  launched app or from the app the user clicked to dismiss the launcher.
- Keep display rules and temporary key bindings scoped to the command session.
  Prefer ordinary completion APIs and the user's configured completion stack.
  Commands that deliberately open other frames may need explicit wrappers;
  arbitrary command compatibility is not promised by this task.

- [ ] Nested prompts stay in the launcher; Escape, C-g, command errors, a second
  invocation and clicking another app leave no leaked recursive edit or prompt
  in a normal Emacs frame.
- [ ] Closing after a successful external action does not reactivate the
  previous app over the action's destination; cancellation restores the previous
  app, and click-away preserves the newly selected app.
- [X] Deleting the frame or disabling during a session cleans up once and a

- [X] Add focused session tests and a real GUI smoke test; existing Portal focus

*** Outcome
Implemented 2026-10-03. =portal-launcher-present= runs one interactive command
with a unique session catch tag. =portal-launcher-command= optionally selects
the shortcut/toggle action; nil preserves plain buffer presentation until the
application integration task. Escape, C-g, repeated invocation, explicit hide,
focus loss, deletion and disable unwind nested minibuffers before cleanup.
Errors propagate after hiding. Deletion/disable finish once outside the session;
normal Emacs selection is restored without activating its application.

Display rules, the cancellation keymap and minibuffer routing are dynamically
scoped. Native preparation captures the previous app before frame creation or
selection. Only cancellation/error cleanup requests focus restoration, gated
by native ownership. Success and external focus changes never request it.

The nonactivating panel can retain AppKit key status after another app takes
input, so resignation alone was insufficient in the real external-activation
smoke test. App-activation observation and a mouse-only global monitor cover
those paths while presented. Hide/detach remove them; no Accessibility event
tap, polling timer or extra process is used. Coalesced =launcher-blur SESSION=
records use the existing pipe and a special command-loop event. Stale records
cannot unwind a replacement session.
