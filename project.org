Add =M-x portal-agents=: one ordinary Emacs buffer listing explicitly tracked
Portal terminals. Like Ibuffer or Dired, it uses text rows, normal movement,
isearch, sorting, =g= to refresh, =q= to quit the window, and =RET= to visit a
terminal. Prefer inexpensive live updates while visible. The dashboard creates
no native or web view and needs no app host or third-party UI package.

*** First version
- Derive =portal-agents-mode= from =tabulated-list-mode= in =portal-agents.el=.
  Keep one dashboard for this Emacs instance, with columns for buffer label,
  assigned project, current directory, terminal title and process state. Include
  an explicitly supplied agent label if available; do not infer it from titles.
- Provide explicit track/untrack commands using ordinary terminal completion.
  Allow hidden and quick terminals. Tracking stores only dashboard-specific
  data, keyed by buffer and native incarnation, never name, path or title.
  Untracking leaves the terminal running. Remove closed/replaced sessions;
  retain exited sessions while their buffers still own the terminal view.
- Distinguish a running terminal process from an exited one. A running shell
  does not prove that its agent is working, idle, waiting for input or successful.
  Agent activity is =unknown= until a verified source exists; do not add an
  attention column with no source. Terminal title is reported text, not a
  generated job summary. Useful navigation must not depend on a status adapter.

*** Refresh policy
- Implement =g= through the mode's revert function first. Refresh on opening
  and redisplaying the dashboard. Keep a usable manual-only setting.
- Enable a single configurable two-second regular Emacs timer while the
  dashboard is displayed in any visible frame. Cancel it when hidden, killed
  or live updating is disabled; restart on display without duplicating timers.
  This is best-effort freshness, not a real-time deadline. Use normal window
  hooks for visibility; no always-running timer just to discover visibility.
- Read cached metadata on each tick and compare the displayed snapshot. If
  unchanged, do not sort or rewrite the buffer. A changed snapshot can use a
  full =tabulated-list-print= with remembered position; preserve the selected
  session, sort choice and each displaying window's position. Do not assume
  its UPDATE argument updates changed columns for an existing row ID.
- Never select a window, focus a terminal, prompt, run a shell command, read
  terminal output, scan task files or perform network I/O during refresh.
  Reuse the existing native collection; add no heartbeat protocol, status
  subscription framework or per-terminal UI timers for this version.

*** Performance and verification
A small cached table should be inexpensive, but that is an expectation to check,
not a benchmark result. Timers execute within Emacs's event processing: slow
callbacks delay editing. Current =portal-terminal-metadata= validates membership
by enumerating views, so reading N rows among V live views costs O(N*V), before
formatting and any sorting. Profile realistic session counts before changing
that shared API. Avoid continuously changing age/counter columns that force
redraws even when agent facts have not changed.

Compare manual-only and live modes at 10, 50 and 100 tracked sessions, both
unchanged and with bursts of metadata changes. Record refresh duration,
allocations/GC, redraw count and typing responsiveness. Hiding or killing the
dashboard must leave no dashboard timer or redraw work; ordinary terminal
metadata collection continues. Increase the interval or retain manual refresh
if live updating noticeably disrupts editing.

Done 2026-10-02. =M-x portal-agents= in =portal-agents.el= shows one
=portal-agents-mode= buffer, derived from =tabulated-list-mode=, with columns
Terminal, Agent, Project, Process (=running= or =exited=), Activity (always
=unknown=), Directory and Title. =portal-agents-track= (=t=; a prefix argument
asks for an agent label) and =portal-agents-untrack= (=u=) take ordinary
terminal completion. Tracking is keyed by buffer and native view target. =RET=
visits through =portal-terminal--visit= and focuses the terminal, and
=portal-agents-toggle-live-update= switches live updates. The defaults are
=portal-agents-live-update= t and =portal-agents-live-update-interval= 2. A
global =window-state-change-functions= hook exists only while the dashboard
does, and refreshes it when it is shown again.

Found while implementing:

- Profiling at 100 tracked terminals showed the =O(N*V)= membership scan in
  =portal-terminal-metadata= was 82% of an unchanged refresh, and 92% beside
  100 more views. The accessor now checks the buffer's own view target, which a
  buffer has exactly while it is registered, as =portal-view--target='s
  docstring now says. Its interface is unchanged. An unchanged refresh at 100
  terminals fell from 4.7 ms and 301 KB to 0.18 ms and 38 KB, whatever the
  number of views.
- The dashboard compares the cached facts before formatting, so an unchanged
  tick never abbreviates directories or names projects. A changed tick reprints
  with =tabulated-list-print=, which is most of its cost.
- =tabulated-list-sort= with -1 restores order from a hash keyed by entry
  objects, so every print rebuilds that hash with tracking order; without that,
  =C-u -1 S= fails after a refresh.
- No window hook reports a frame being made invisible, so each tick checks
  visibility itself and stops the timer. Live updates restart at the next
  window change, such as selecting the frame.
- In graphical Emacs outside the command loop, =sit-for= returns at once while
  input is pending: a benchmark wait loop spun and allocated about 35 MB/s. The
  GUI tests and the benchmark wait with =accept-process-output= instead.

*** Measured mechanism
From [[file:docs/agent-discovery-research.md][the spike's research note]],
tested with Claude Code 2.1.287. No Claude setup is needed.

  =KERN_PROC_UID= snapshot, keeping processes whose group owns their TTY, then
  reading =argv[0]=, arguments and the marker; skip NUL padding before the
  environment. Name a process by the basename of =argv[0]=, or of its script
  argument when that is =node=, =bun=, Deno, Python or a shell, as Herdr does,
  and accept the name only when the executable agrees: the agent's own binary
  (for Claude, under =claude/versions/=) or a runtime. Claude is =claude= (its
  =comm= is its version number), npm shims run =node .../bin/claude=, and
  =exec -a claude sleep= is rejected. Ignore an agent nested under another
  agent in the same terminal. Per the platform-primitives rule, the platform reports processes;
  Lisp or the core classifies them. [[file:docs/agent-discovery/agentscan.c][agentscan.c]]
  is the reference. Also cache each terminal's last OSC 9;4 progress state and
  announce changes through the existing change records.
- *Activity:* run =claude agents --json= asynchronously, one at a time, only
  while the dashboard is shown: when shown, for a PID with no status (at most
  every 4 s while unlisted), when a Claude terminal's title glyph class (=✳=,
  a spinner in U+2800–U+28FF or =◐=–=◓=, other) or progress state changes, and
  every 30 s. A trigger that arrives while a query runs is remembered, even if
  the title and progress change back before it ends, and starts another query
  when it finishes: the running one may have sampled a state that has passed. Claude changed its spinner at 2.1.228; progress and the poll
  cover a later change. Map =busy=,
  =waiting=, =idle= by PID and process start; otherwise =unknown=, with a reason
  (not yet listed, trust dialog, query failed). [[file:docs/agent-discovery/prototype.el][prototype.el]]
  shows the rules against the current dashboard.

  starting while the dashboard is shown, and at once when it is opened or shown
  again. Activity within 1 s of the terminal's title or progress change. Measured:
  process visible 0.17–0.73 s after Enter; statuses 0.2–0.6 s after the signal.
