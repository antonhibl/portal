The initial import from =tasks/= preserved 24 tasks: 1 TODO and 23 DONE. New work
is authored here. Plans, checklists, decisions, and verification stay with each task.
The Markdown originals are retained for comparison with the current task browser.

Use TAB to fold a task, C-c C-t to change its state, and C-c C-x b to edit just
its subtree in an indirect buffer; =RET= in =M-x portal-tasks= does the same.
Task headings carry the =task= tag; org-ql can query this file directly without
adding it to a global agenda. =CANCELLED= closes a task without completing it.

Each task has a stable Org =ID= and a readable =CUSTOM_ID= preserving its previous
Portal task ID. =DEPENDS_ON= lists prerequisite CUSTOM_IDs in this file or its
archive, =project.org_archive=; the existing dependency descriptions link to those tasks. This is explicit metadata,
not built-in Org enforcement. Groups and prose links imply no dependencies.
=SOURCE= records the original Markdown path. Existing states and checkbox marks
are preserved independently; completion dates have not been invented.

* Launcher :launcher:
The first milestone is a global macOS application launcher whose UI is a real
Emacs buffer. Portal supplies a small native presentation layer; Elisp keeps the
commands, completion and customization. The existing =launcher.el= supplies the
first command. Later M-x.app features, including URL scheme handling,
=org-protocol=, modifier double-taps and multiple shortcut bindings, are outside
this milestone.
